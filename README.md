# photomosaic_cpp

たくさんの小さな写真（タイル）を並べて、1 枚の大きな写真を描くフォトモザイク。
本体は C++ のヘッダオンリー（`cpp/photomosaic.h`、依存なし）で、WASM にしてブラウザだけで動かす。

**デモ: https://yomei-o.github.io/photomosaic_cpp/**

1. 元にする写真を選ぶか、カメラで撮る
2. タイルにする写真をまとめて選ぶ（複数選択・カメラで追加も可）。手元に無ければ「元の写真を切ってタイルにする」
3. 横のマス数・色寄せ・使い回しにくさを決めて「モザイクを作る」。拡大して見る・画像を保存

写真はすべて端末の中（Web Worker 上の WASM）で処理し、どこにも送らない。

## しくみ

- **色の比べ方**：マスとタイルをそれぞれ 3×3 に区切り、9 か所の平均色を Lab 色空間（人の目の色差に近い）で比べる。
  平均は線形 RGB で取ってから Lab にする。平均色 1 つで比べるより、マスの中の明暗の向きが合う。
- **色寄せ後のずれで選ぶ**：描くときにタイルの平均色をマスの平均色へ「色寄せ」の割合だけずらすので、照合も
  ずれ_k =（マス_k − タイル_k）− 色寄せ ×（マス平均 − タイル平均）で測り、明るさ L の差は 2 倍に重く見る。
  平均の色合いは後で直るぶん、明暗の形が合うタイルが選ばれる。
- **偏りを防ぐ**：マスを乱数の順に埋める（左上から順だと後半ほど良いタイルが残らない）。使った回数ごとにコストを
  (1 + 使い回しにくさ) 倍し（既定 0.05）、半径 2 マス以内には同じタイルを置かない（タイルが足りなければ外す）。
- iPhone の写真は向きが EXIF にあるので、`createImageBitmap(file, {imageOrientation: 'from-image'})` で読む。
- 出力は長辺 4096 画素まで（iPhone の canvas の上限）。タイルは 64×64 で持つ。

## 速さ（PC の Node、タイル 300 枚、60×45 マス、出力 1920×1440）

割り当て 0.1〜0.2 秒、描画 0.2〜0.5 秒。ブラウザで 3840×2880 を作って 0.8 秒。

## ビルドと試験

```
sh build_wasm.sh                 # docs/photomosaic.js（wasm 埋め込みの 1 ファイル）
python tools/fetch_testdata.py   # 試験用の写真（picsum.photos）
node tools/try_node.js target_23 60 32 0.25   # build/ に Python で用意した RGBA が要る（RESUME.md 参照）
```

## 顔での実験（2026-11-26、`tools/experiment.py`）

顔は肌色に偏っていて、色の幅が広い写真の集まりからは合うタイルが少ない。自撮り写真 1 枚（リポには入れていない）、
サンプルの名画タイル 300 枚、横 80 マスで比べた。ΔE はモザイクと元写真を横 160 に縮小して測った Lab 色差の平均。

| 照合 | 色寄せ | ΔE | 明るさのずれ |
|---|---|---|---|
| 平均色のまま比べる | 0% / 25% / 40% | 11.72 / 9.48 / 8.21 | 6.59 / 5.67 / 5.19 |
| 色寄せ後のずれ＋明るさ 2 倍 | 0% / 25% / 40% | 11.90 / 9.65 / 8.29 | 5.96 / 5.16 / 4.67 |

新しい照合は色差は同じくらいで、明るさのずれ（目鼻の陰影）が約 1 割小さい。肌に赤い絵が点々と混ざる外れは、
肌色のタイルを使い回しの罰で使い切るのが原因で、罰を弱めると減った（色寄せ 40%）：

| 使い回しにくさ | ΔE | 明るさのずれ | 色の外れたマス | 使った種類 |
|---|---|---|---|---|
| 0.15 | 8.29 | 4.67 | 73 | 300 |
| 0.05（既定） | 7.95 | 4.26 | 43 | 282 |
| 0.02 | 7.76 | 4.01 | 36 | 254 |
| 0 | 7.82 | 3.99 | 56 | 200（同じ絵が固まって縞になる） |
